# 热点站点维护记录

## 当前实现

热点配置位于 `config/hotspot/site.json`，仅 root 可读写；自签证书保存在同目录，私钥不通过普通配置读取返回。模块管理器入口打开独立 WebUI，复用 `config read/apply` 和已有 Worker，不新增常驻进程。启用要求 raw 模式；自定义域名、黑名单及精确例外投影到 sing-box 的 raw 配置副本，下载原文不变。页面导出 JSON 备份可能包含用户提供的私钥。

Worker 根据 nl80211 AP 类型识别热点接口，增加 `192.2.0.1/32`，使用 Go 标准库提供 HTTPS/HTTP2。网络变化及配置唤醒触发重估，关闭或切换接口时清理自有地址；运行中重启后的地址所有权记录位于 `/dev/netproxy/hotspot-lease.json`。监听状态位于同目录的 `hotspot-status.json`。用户已有的相同地址不归模块所有，不主动删除。DNS 原配置需要接管客户端请求，静态 DNS 规则本身不创建 DNS 入站或防火墙规则。

## 验证与后续

已覆盖 DNS 规则优先级与内核配置解析、原文保留和候选校验、配置修订冲突及私钥隐藏、HTTP/2 应答与停止、Worker 启停及地址所有权清理。2026-11-21 的 quick、WebUI 和文档验证通过，同版本 sing-box 主机编译接受 DNS 投影，并发测试通过。窄屏浅色、深色、加载和错误状态的截图位于 `.agents/runs/2026-11-21-hotspot-site/`；使用模拟模块桥接验证读取、编辑、保存和读取失败，不代表设备测试。

尚需在真实 Android 热点验证 nl80211 接口识别、多热点、地址绑定与关闭清理、热点客户端路由和防火墙，以及 raw 配置的 DNS 接管。测试自签证书信任、系统重启/Worker 异常退出恢复和端口冲突。`192.2.0.1` 是公网地址空间，使用时该地址的公网流量会落到本机；用户已接受此冲突。发生问题时优先检查页面状态与服务日志，不能自动选择其他 IP 或覆盖其他接口的地址。
